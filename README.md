# Lorebook Lab（ロアブック検証ラボ）

Zeta・Zetter などのAIチャット向けロアブックについて、登録キーワードが会話文のどこに一致するか、誤発火や拾い漏れがないかを確かめる静的Webアプリです。

> **このツールは実機の発火状態を取得しません。** 文字列一致から「発火候補」を出す模擬判定です。

- サーバー不要。すべてブラウザ内で処理し、入力した会話やロアブックを外部へ送信しません
- データはそのブラウザの `localStorage` にだけ保存します（「管理 → すべてのデータを削除」で消せます）
- スマートフォン操作を前提にした画面です

## 判定の前提

実機での検証結果に合わせて、次のように判定します。

| 前提 | このツールでの扱い |
| --- | --- |
| 大文字小文字・全角半角・ひらがなカタカナは変換されない | 変換しない。登録した文字列そのものとの部分一致だけを見る |
| 活用形は補完されない | 補完しない（「急が」は「急がない」に一致、「急ぐ」には不一致） |
| 1項目のキーワードは最大5個 | 6個目以降は照合に使わず、警告を出す |
| 一致した項目は次のターンの生成1回に影響する | 連動分析で「次のAI生成に影響しうる候補」として表示 |

表記を変えれば一致する箇所（「ほっと」と「ホッと」など）は、判定には含めず「表記ゆれで拾えていない箇所」として別に表示します。

## 画面

| タブ | できること |
| --- | --- |
| 照合 | ユーザー発言とAI生成文を別々に入れ、一致した項目・キーワード・位置（何文字目）・回数・一致しなかった項目を表示。一致箇所ごとに「適切／不適切」を記録できる |
| 監査 | **監査ケース**：例文と「一致してほしいか」を登録し、誤発火候補・拾い漏れを判定。**手動の記録**：照合タブでの判断を一覧・書き出し。**設計点検**：5個上限・重複・キーワードの包含・1文字キーワード・日常語との一致・本文に含まれるキーワード（連鎖の可能性）を点検 |
| 比較 | 旧版と新版を同じ文で照合し、両方で一致／旧版のみ／新版のみ／キーワード変更による拾い漏れを表示。キーワードと本文の変更点も一覧 |
| 連動 | 会話をターンに分けて入力し、各AI生成に影響しうる項目を時系列で表示。AI生成文由来の候補、同じ項目が続けて候補になる回数も出す |
| 管理 | ロアブックの読み込み（Markdown／JSON、ファイルまたは貼り付け）、編集、複製、書き出し、削除。AIに出力させるための指示文のコピー |

## ロアブックの Markdown 形式

```markdown
# ロアブック名 v0.3

## 分類名（任意）

### 01｜項目名

**キーワード：** 語1、語2、語3、語4、語5

**本文：** 登録本文
```

- `### ` の見出しが1項目です。番号は `01｜` `1.` などで区切ります（なくても可）
- キーワードは「、」「,」「/」で区切ります。「」や引用符は外して読み込みます
- `- キーワード: …` のような箇条書き、半角コロン、コードブロック（```markdown）で囲まれた出力も読めます
- `---` 以降や項目外の文章は、項目ではなくメモとして保持します

ChatGPT や Claude でロアブックを作った場合は、「管理 → AIに出力させるための指示文」をコピーして送ると、この形式で出力させられます。

## 公開（GitHub Pages）

1. リポジトリの **Settings → Pages** を開く
2. **Build and deployment** の Source を「Deploy from a branch」、Branch を `main`・`/ (root)` にして保存
3. 数分後に `https://<ユーザー名>.github.io/lorebook-lab/` で開けます

## 手元で動かす

`index.html` をブラウザで直接開くだけで動きます（ES Modules や fetch を使っていないため）。

ローカルサーバーで確認する場合：

```sh
python3 -m http.server 8080
# → http://localhost:8080/
```

## テスト

```sh
npm test            # 照合・読み込み・監査・比較・連動の自動テスト（Node.js 18以上）
npm run report      # テストとスマホ幅の表示確認を実行し TEST_RESULTS.md を更新（Playwright が必要）
```

最新の結果は [TEST_RESULTS.md](TEST_RESULTS.md)、画面は [docs/screenshots/](docs/screenshots/) にあります。

## ファイル構成

```
index.html              画面の骨組み
css/style.css           デザイン（ライト／ダーク）
js/core/matcher.js      文字列一致エンジン（部分一致・位置・表記ゆれ候補）
js/core/parser.js       Markdown／JSON の読み込みと書き出し、AI用指示文
js/core/audit.js        監査ケースの判定、設計点検、初期の語彙リスト
js/core/compare.js      バージョン比較
js/core/chain.js        複数ターンの連動分析
js/data/sample.js       サンプル（samples/ から自動生成）
js/app.js               画面と保存
samples/lorebook_v03.md 描写演出ロアブック v0.3（テストデータ）
tests/                  自動テスト
scripts/                サンプル生成・1ファイル版の作成・表示確認・テスト結果の作成
```

判定ロジックは `js/core/` にまとまっていて、画面（`js/app.js`）とは分かれています。どのファイルもブラウザでは `window.LL.*`、Node.js では `require()` で使えます。新しい分析を足すときは `js/core/` にモジュールを追加し、テストを書いてから画面につなぎます。

サンプルを差し替えたときは `npm run build:sample` で `js/data/sample.js` を作り直してください。

## 注意

- 一致したかどうかは機械で判定できますが、それが場面として適切かどうか（意味的な誤発火か）は判定できません。監査ケースと手動の記録で判断を残す設計です
- 設計点検の語彙リストは初期値の例です。自分の会話で出やすい語を足すほど実態に近づきます
